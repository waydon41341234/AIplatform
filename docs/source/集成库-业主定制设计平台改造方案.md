# 集成库 → 业主定制设计平台改造方案

日期：2026-11-20  
状态：方案评审稿，尚未开始产品改造。

## 首要体验原则：非技术业主容易使用

用户明确：大部分业主不是技术人员，平台必须简单易用。下文所有功能以此作为默认交互约束：业主主要选择、预览和确认，系统承担规格、图层、Key 映射、提示词拼接及交付检查。功能完整性不通过向业主展示所有技术参数来实现。

### 默认流程

1. **选模板**：用真实页面缩略图选择版式；新项目自带完整页面和默认素材，避免空白画布。定制范围确定后，自动列出需要完成的页面。
2. **定品牌**：上传 Logo、选择整套推荐配色并确认 11 个基础色。色块按主色、文字、背景、辅助色分组，用真实页面即时预览。业主可调整每色，但不需要从零输入 11 个 HEX。
3. **改页面**：点击页面区域即可选择“换素材”“改文字”“选效果”；支持点选替换，也保留拖放拼接、模块排序和允许的布局选择。必交项由任务清单引导。
4. **预览并交付**：查看整套页面，按可定位的问题提示补齐设计，然后导出 Figma 源文件、PNG、SVG。

允许随时返回前一步；自动保存并支持撤销、恢复已采用版本。每一步只有一个明确主操作，次要操作放入对应模块。小屏先提供预览、简单替换与确认，复杂排版在桌面完成。

### 给业主看的内容

| 业主界面 | 系统 / 高级设置处理 |
| --- | --- |
| “主色”“次级文字”“页面背景”等用途名称与色块 | 原始 Key、引用关系、HEX、透明度与条件规则 |
| “后台可更换入口”“入口固定”，配一句必交说明 | 原配置模式、入口枚举及必交矩阵 |
| “玻璃质感”等标签、悬停效果图、整组款式参考 | 结构化提示词、图标语义、状态约束及模型参数 |
| “换素材”“生成新图”“采用这一张” | 规范像素、@2x 倍率、图层位置、裁切处理和资产版本 |
| “正常”“选中”“已读”“未读”等状态 | 状态字段与素材绑定 |
| “预计费用”“余额”“生成进度” | 供应商、API Key、费率、调用编号、预留与结算账本 |
| “这张图尺寸不合适，点击调整”“缺少公告图标” | 可定位的校验结果；不向业主展示异常堆栈 |
| “导出 Figma 源文件”“导出 PNG”“导出 SVG” | 原生文件生成、资源解析、变量绑定和文件打包 |

Key 不作为业主默认必填字段。组件按语义自动绑定，颜色面板显示中文用途；需要查看或调整 Key 的用户可展开高级设置。“锁定绑定”用“保持此颜色用途关联”等说明呈现，避免用“固定颜色”误导业主认为 HEX 不再联动。

自动操作不得触发未确认收费。选款式、选效果、调整配色和预览不自动生成；生成前明确展示当前素材/批量范围及预计费用，失败信息说明已保留内容及费用状态。

模板、款式和推荐色板使用少量精选选项起步，支持再展开更多。提示词无需业主编写，可用一句自然语言补充要求；专业模型、坐标与参数隐藏在高级设置中。H5/PC 默认按项目范围组织，不能用技术切换项淹没主要操作。

### 易用性验收

开发后邀请真实非技术业主试用：是否无需开发人员指导就能新建项目、确认配色、替换图标、理解收费、返回修改并导出文件；是否能看懂必交项与错误提示；是否能恢复误操作。记录完成耗时、求助点与失败原因，以实际试用结果修改交互，不只检查页面是否漂亮。

易用性不减少既定目标：11 类页面范围、规范尺寸、图标 @2x、配置模式、68-Key 规则、效果预览、费用归属和真实 Figma 源文件交付仍全部保留。

## 当前界面：业务主题改为定制版等级（方案，未实施）

用户明确本次只制定方案，不修改代码。依据截图，将创作区域现有“选择业务主题”及“全部业务、博彩、棋牌、电子……”选项替换为“选择定制版等级”，提供普通定制、高级定制、全方位定制。此位置的行业词条数量及行业说明同步改为等级说明；不得仅替换按钮文字、仍在内部按旧行业筛选。

### 等级选择的呈现

使用三个有文字说明的单选选项，桌面并排，小屏纵向或自然换行，不能依赖横向滑动寻找等级。清楚显示当前选中项；建议初始默认普通定制，业主可直接更换。

| 选项 | 简短说明 | 设计范围 |
| --- | --- | --- |
| 普通定制 | 定制首页与基础公共模块 | 首页、彩金池、页脚、菜单栏，共 4 类 |
| 高级定制 | 增加登录、下载及个人页面 | 普通范围 + 登录注册页、下载引导条、APP 下载弹窗、游戏二级页、我的页面，共 9 类 |
| 全方位定制 | 覆盖完整定制范围 | 高级范围 + 优惠中心、推广，共 11 类 |

下方用“当前可设计：……”说明所选范围，提供简洁的页面/模块清单。H5 按等级开放对应内容，PC 按已核定规范仅覆盖首页、彩金池、页脚、菜单栏；不能因为选全方位就自动承诺所有页面的 PC 独立设计。

### 与后续设计区域的关系

等级是项目设计范围，不能作为素材行业或画风筛选。选定等级后，下一步选择具体页面/模块，再展示对应组件、参考款式、规范素材及提示词。例如先选普通定制，再选首页中的 Banner、游戏卡片或导航图标；首页九模块仍按既定方案组织。

当前“搭配提示词”区域在后续改造中应根据选中的页面/素材展示适用内容；图标提供款式与关键效果预览，Banner 提供已登记的样式参考。选择等级本身不提交 AI 请求、不收费，也不自动把“高级定制”等等级名加入生图提示词。

### 切换与保存

项目保存独立的定制等级字段，不复用旧行业字段。等级升级后增加可设计清单；降级后显示哪些内容不在当前范围，并保留其草稿、素材和历史。当前交付仅包含所选等级范围，范围外内容不计为缺失，不自动删除，也不能偷偷夹入正式交付。

切换等级不清空已采用素材、配色、提示词草稿和生成历史；原行业草稿不通过按钮文字猜测映射为等级。旧行业筛选若后续仍有使用价值，应放入具体素材选择的高级筛选，不能继续占据这个等级选择位置。

### 验收目标

- 该位置只有三个清楚的等级选项，不再显示行业词条统计与行业介绍。
- 等级范围与定制说明一致，可设计清单和交付清单同步变化。
- 切换后设计不丢失，不触发 AI 生成或扣费。
- 手机可直接看懂并选择三种等级，当前选择明确。
- 本节仅为后续改造方案，当前平台代码仍保持本次操作前的状态。

## 最新确认的产品要求（2026-11-20）

用户补充后，本方案以以下要求为准：

- 平台采用低代码式页面搭建。业主可以自行拼接图标、素材与组件，支持模块排序、分栏、间距、对齐与装饰层摆放；常规业务组件用流式布局，装饰层允许自由定位。
- 三个资源入口为「上传资源」「AI 生成」「集成库参考素材」。素材完成检查并被采用后，可以拖入画布或替换组件中的对应素材。
- 可设置全局及局部配色、字号。业主先设置 primary、lead、neutral_1、neutral_2、neutral_3、border、bg_1、bg_2、accent_1、accent_2、accent_3 共 11 个基础色；其余 57 个 Key 按用户色值规范映射，包含引用、固定色、透明度、条件规则和跟设计配色。页面元素完成配色后绑定并锁定到语义 Key；字号提供标准档位及各组件允许的选项。
- H5 新建画布默认 750×1334px。内容溢出时显示提示，由业主选择增加页面高度或调整布局，不默默裁掉内容。该默认值由用户指定；原 Figma 说明只规定宽度 750px、高度不限。
- 游戏卡片、Banner、中部导航图标、底部导航图标、游戏类型图标必须采用平台规范尺寸。业主可改变画面设计，但不能任意改变这五类素材的交付宽高。用户要求优先于原说明的“参考尺寸”和“尺寸可自定义”。
- 三类图标增加 @2x 输出：底部导航 70×70 → 140×140px，中部导航 80×70 → 160×140px，游戏类型 100×76 → 200×152px。Figma 仍按原规范逻辑尺寸展示；素材规范增加倍率，不能把 @2x 文件误判为尺寸不合规。具体见「图标 @2x 输出」补充。
- 完成后必须交付真正可编辑的 Figma 源文件，同时支持 PNG、SVG。Figma 交付不能退化为整页图片、仅有 SVG 或项目 JSON；三者的可编辑程度和导出路径见下文。

### 强制尺寸目录

| 素材 | 首批规格 / px | 编辑规则 |
| --- | --- | --- |
| Banner | 大 1080×490；通用 1020×300；小 386×244 | 选择规格后锁定素材宽高，画面可重新设计 |
| 中部导航图标 | 80×70 | 锁定交付画布，允许调整图形在画布内的占比 |
| 底部导航图标 | 70×70 | 默认/选中状态采用同一规格和对齐基准 |
| 游戏类型图标 | 100×76 | 锁定交付画布，保持整组视觉大小一致 |
| 游戏卡片 | 180×180、520×203、300×400、300×300、400×250 | 依据说明的卡片样式选择；同尺寸的不同样式分别保留角标、收藏和兜底规则 |

卡片目录需把说明中的 A1–A7 样式逐一登记，不能只按宽高去重。自定义画面使用其中一个已登记规格；新增尺寸由内部维护规范目录后开放。**规范逻辑尺寸、资源像素尺寸、页面显示尺寸分开。** 例如 1020×300 的 Banner 可以在 H5 中按比例显示为 710×约209px，但独立素材导出仍为 1020×300。三类图标按本方案补充规则输出 @2x 像素，并按原规范逻辑尺寸摆放。画布拖动不能随意拉伸标准素材；SVG 需检查宽高与 viewBox，不能只检查文件后缀。

上传不合规素材时，先提示目标尺寸并提供裁切、留边或重新上传。转换前显示结果并让业主采用；不静默拉伸。小图放大即使满足像素宽高，也需提示清晰度问题。AI 同样先生成，再转换、检查并采用，不能依赖提示词保证精确像素。

### 三种导出的实际含义

| 格式 | 交付内容 | 可编辑边界 |
| --- | --- | --- |
| PNG | 整页/指定模块预览，以及原始规范尺寸的独立素材 | 为图片，不能继续逐层编辑 |
| SVG | 页面或组件的矢量布局、形状与文本，按需嵌入位图素材 | AI 图片和上传照片仍为嵌入位图，不自动成为路径；需要提供字体处理选项 |
| Figma | 真正的原生 Figma 设计文件，包含可编辑页面、组件、文本、布局和素材层，并提供文件链接及本地 .fig 副本 | 位图保持图片层；需通过 Figma 插件或支持原生节点的导入通道落入文件 |

「下载 .fig 文件」与「导入 Figma 可编辑设计」是不同实现。产品验收必须覆盖两者：先通过 Figma 插件或支持原生节点的导入通道生成可编辑文件，再从 Figma 保存原生 .fig 本地副本并纳入交付。平台内一键自动下载 .fig 的通道需要先做技术验证；若不能稳定自动化，就在导出流程中明确引导从 Figma 保存副本，由内部交付流程核验文件。不能把 PNG、SVG 或项目 JSON 改名为 .fig。

最先实施一个 Figma 源文件验证样板：至少包含两个页面、可编辑文本、可更换图片、矢量图标、自动布局/组件、主题颜色和字号。导入后重新打开 Figma 文件，实际修改文本与组件，再从 .fig 本地副本恢复并核对图层、尺寸、素材和字体。此验证未通过前，不进入大规模页面开发，也不能宣称 Figma 交付能力完成。

SVG 默认提供保留文本的版本，并提示字体依赖；需要完全固定字形时可提供转路径版本，但文字将失去文本编辑能力。页面中的链接和业务行为不会因导出 SVG 就获得完整应用交互能力。

### 必须解决的设计问题

1. **拼接自由度**：页面模块可以增加、删除、排序、分栏；业务组件的内部字段和必要操作保留结构约束，避免业主误删登录字段或下载入口。自由布局用于装饰层，整页仍要遵守支持的组件与规范。
2. **长页面和状态**：750×1334 是默认设计画布，不代表所有页面都只能容纳一屏。需同时处理页面高度、滚动区域、固定导航、安全区域和弹窗层；H5 预览要在常用实际设备宽度验证。
3. **字号与颜色**：组件允许的字号需要与间距、按钮高度和文案长度配套校验；字号修改不通过缩放整张素材实现。图片内置文字不属于可编辑字号选项；需要可编辑时用独立文字层。
4. **资源来源**：集成库需要区分可直接使用的独立素材、可编辑组件和仅作风格参考的页面截图。截图不能被当作已拆分组件；采用素材记录来源，私有项目素材不能默认进入公共参考库。
5. **统一设计数据**：采用同一份页面/组件/素材/主题结构驱动画布和三种导出，保留位置、尺寸、图层、文本、字体、引用与状态。不能靠整页截图来重建 Figma 可编辑图层。
6. **跨格式一致性**：模糊、阴影、混合模式、蒙版、渐变和字体可能在 SVG/Figma 中表现不同。先定义跨格式支持的效果集合；需要栅格化的效果提前提示，验证导出后视觉与层级一致性。
7. **编辑可靠性**：支持撤销/重做、复制、锁定、自动保存、候选采用与恢复版本；生成失败不覆盖已采用素材，共用组件修改需显示影响范围。

以上属于方案修订，尚未实现。开发前优先用一个包含图片、图标、文字、布局和阴影的首页样板，验证标准尺寸与三种导出的闭环。

## 1. 产品定位与目标

把现有集成库改为业主能够独立完成定制版素材与 UI 设计的工作空间。业主即使没有外包设计师，也能按照公司的定制说明，选择版式、设定品牌风格、制作素材、调整页面并交付一套可核对的设计。

建议主入口名称为「定制设计」，首页主操作为「新建定制项目」。以项目和页面组织低代码搭建，上传、AI 生图、集成库素材、Banner、节日皮肤作为项目中的制作能力。

最终交付目标是：统一风格的页面设计、符合规格的独立素材、色表与页面配置、完整交付清单。平台帮助完成设计；业务系统接入和上线仍需要按公司的现有实施流程处理。

| 游戏类型图标 | PNG、SVG；尺寸参考 100×76px | 可以选默认图标或自制，必须明确最终采用的设计 |
| 中部导航图标 | PNG、SVG；尺寸参考 80×70px | 按“可后台配置 / 不可后台配置”选择不同必交清单，详见本文件导航图标补充规则 |
| 底部导航图标 | PNG、SVG；尺寸参考 70×70px | 按“可后台配置 / 不可后台配置”选择不同必交清单，详见本文件导航图标补充规则 |
| 游戏平台卡片 | PNG、SVG；原说明尺寸可自定义，列出多种样式 | 按用户新要求锁定已登记规范尺寸，绑定所选卡片及配套角标规则 |
| 页面输出 | Figma、PSD、PNG、HTML | 分阶段支持；图片预览不等同于可编辑源文件或可接入的 HTML |

尺寸中的“限制”和“参考”保留来源标记；用户指定的五类素材即使原说明标为参考，也按规范目录强制校验。其他规格按说明处理。11 色指业主先确定的基础色输入；完整色值规范包含 68 个 Key，不限制所有图片或扩展色只能出现 11 种颜色。具体规则见 [色值Key绑定规范](./色值Key绑定规范.md)。

说明中的 pt 字号保留原单位；转换为预览 CSS 和导出规格时需要确定映射，不能直接把 pt 数字当成 px。

### 当前集成库

现有实现为 Node.js 服务、原生前端及 Python 图片处理，服务监听 127.0.0.1:4318。已有能力包括 AI 图片生成、提示词库、Banner、节日皮肤、部分动效与分层交付、生成历史。

UI 设计代码和服务保留，但 public/app.js 中 UI_DESIGN_ENABLED=false，入口目前已下架。其原实现以 750×1334 画布和模块坐标合成 PNG，模块尺寸属于旧业务建议值，不能直接当成此次 Figma 规范。

Banner 现有选项包含多个 1020×300 别名和 1080×490，大、小、通用三个标准规格尚未完整对应，小 Banner 386×244 需要补齐。

当前没有证据表明已具备业主账户、项目权限、多人协作或在线验收流程。部署为业主可访问的平台需要专门建设这些能力，不能只把本地服务地址换成公网地址。

## 3. 业主的完整操作流程

1. **创建项目**：输入品牌名称，选择定制范围、版式、目标端和语言。系统自动生成本项目页面与素材清单。
2. **建立统一风格**：上传 Logo、选取模板或参考图，业主先配置 11 个基础色；系统按 68-Key 规范映射，并结合版式确认“跟设计”配色，先查看首页样板。参考图只用于表达风格，品牌与游戏标识优先采用授权的已有素材。
3. **确认样板**：业主在页面中确认整体方向，再应用到其他页面。应用主题可先预览影响范围；已单独定制的内容提供保留选择。
4. **逐页定制**：选择页面中的具体区域，替换现成素材、上传图片或 AI 制作；修改文案、配色及允许调整的布局。
5. **补齐设计**：系统提示缺少的必交素材、未确认的图标、相关页面和状态；默认方案也可以通过业主明确确认后纳入交付。
6. **预览与检查**：切换 H5/PC 支持的页面、登录状态、菜单选中状态和多语言；查看自动检查及需要人工确认的问题。
7. **确认与交付**：形成一个固定版本，下载页面图、素材包和规格清单。未来上线阶段可增加内部审核，审核通过后生成正式交付版本。

业主看到的是“为首页替换 Banner”“统一底部导航图标”“修改登录宣传图”等具体任务。模型、提示词和坐标参数放到高级设置中，常规流程用清晰的选项和即时预览完成。

## 6. 页面编辑器方案

推荐采用低代码组件编辑器，提供页面模块拼接、受控的版式变化、规范素材替换、配色和字号设置。

- 左侧：本项目的页面/模块树，显示待设计、已有候选、已采用、已确认和需重新检查。
- 中间：可交互的页面预览，点击区域选中模块；H5/PC 切换只显示该页支持的端。
- 右侧：当前模块的文案、主题、素材和布局选项，显示说明中的尺寸与要求。
- 顶部：项目名称、版本、保存状态、全局主题和整套预览。
- 主要操作：替换素材、生成候选、采用方案、恢复上一版、检查交付。

桌面为主要编辑环境；小屏优先提供浏览、简单修改、确认和下载，不强行缩小三栏编辑器。

素材采用后自动回填页面。候选生成失败时保留已采用版本；同一素材用于多个页面时，替换前显示影响页面。统一主题更新后，HTML/CSS 外观直接更新；依赖旧主题的生成图片标为需检查，避免悄悄重新生成。

## 7. AI 与确定性页面渲染的分工

AI 适合生成宣传图、背景、装饰、卡片画面及风格候选。页面的文字、按钮、表单、金额、链接、二维码和导航结构由模板与代码生成，保障可编辑性和数据展示能力。

完整页面图片可以用于早期风格确认，但不能直接作为最终可用 UI。建议正式预览由组件、样式和独立素材渲染，再导出页面 PNG。

整套风格通过项目主题、已确认的样板、素材风格参考和模板约束保持一致。生成结果提供候选比较与单项重做，由业主采用后才写入正式设计。

成本控制：优先复用默认素材和已采用设计；开始生成前显示本次范围、调用数量和平台配置的额度估算；先完成样板再铺量。失败、取消和重启后保留成功结果，继续时仅补缺项，不自动重复提交收费生成。未来服务端需要项目任务队列和可核对的用量记录。

图标可以选择内部默认 SVG、上传 SVG 或生成 PNG；AI 生成的 PNG 不能通过更改扩展名冒充 SVG。现有去底流程可复用，但透明边缘和视觉一致性仍需要人工核对。

## 8. 项目、版本与交付

建议基本对象为：项目 → 主题 → 页面模板与配置 → 素材槽位 → 素材版本 → 交付版本。生成任务独立记录，并与项目、槽位和请求快照关联。

一个槽位同时保留“已采用版本”和“新候选”；修改需求后标记旧素材的适用状态。浏览器草稿不能承担正式项目保存，项目与版本需要服务端持久化。

首期交付包建议包含：

- pages/h5/：所选 H5 页面与必要状态的 PNG、SVG。
- pages/pc/：前四类所选 PC 页面与必要状态的 PNG、SVG。
- assets/：已采用的独立图片和真实 SVG，按用途、端与状态命名。
- theme.json：11 个基础色、完整 68-Key 映射/覆盖、条件模式、颜色绑定和锁定状态，以及字号和间距映射。
- project.json：页面、模板、素材引用与布局配置。
- manifest.json：文件名、像素尺寸、格式、透明度、来源和版本。
- delivery-checklist.md：必交项、默认素材采用情况、自动检查及人工核对结果。

Figma 交付按项目生成可编辑设计文件、文件链接和本地 .fig 副本，并在清单记录对应页面与版本。若文件需要通过插件写入业主自己的 Figma 空间，导出界面应明确说明连接及授权步骤；副本从该原生文件保存，且需验证能重新打开并编辑。

用户指定的 PNG、SVG 和 Figma 设计为目标交付格式，按本文件开头的导出边界实施并验证。HTML 和 PSD 不作为本次默认交付；如后续需要，分别核定接入契约与可编辑源文件能力。

按所选项目生成清单，必交项、默认采用项、可后台自行替换项分开显示。完整度按本项目实际范围计算，避免通过把所有可选功能都设为必交来限制业主。

## 9. 从本地工具到业主在线平台

方案阶段以现有本地代码为基础，先验证设计流程。业主在线使用的发布前条件包括账户登录、项目访问隔离、服务端存储、文件上传管理、生成任务队列、额度控制、私有素材访问及版本记录。

账号方案可接公司已有登录体系，也可单独建设；在确定现有身份服务前不预设具体供应商。模型网关配置由服务端管理，业主通过平台使用生成能力。

建议角色为业主和内部管理员/审核人员。业主管理自己的项目；内部人员维护模板、规范及默认素材，并在需要时处理设计审核。设计师协作可以后续增加，不作为业主独立完成工作的前提。

### GitLab 存储与业主访问边界

用户计划用 GitLab 存放代码和素材。默认采用内部私有仓库，无需为了业主使用平台而申请公开或对外开放的 Git 仓库。业主不需要 GitLab 账号、Git 客户端或仓库权限。

- 平台代码在私有 GitLab 仓库开发、评审、构建和发布。
- 规范、模板、参考素材及正式交付版本可在私有素材仓库维护；较大的 PNG、.fig 和交付包应评估 Git LFS、容量、备份与保留规则。
- 草稿、生成任务状态、权限和项目元数据由平台数据库/持久化服务管理；高频上传与 AI 候选通过应用文件存储或对象存储承载。需要版本归档时再同步到 GitLab，避免每次编辑都提交二进制文件。
- 平台后端通过服务身份访问 GitLab，凭据不下发给业主浏览器。素材经过平台鉴权后展示或下载，不能直接把内部仓库 raw 地址作为对外交付地址。
- 业主通过平台登录、新建项目、上传素材、编辑设计和下载交付包；只能访问自己的项目与获准使用的公共参考素材。私有项目素材不因放入同一 GitLab 实例而自动对其他业主开放。
- 对外需部署可访问的平台服务、域名及相应登录与网络访问机制。GitLab 可继续留在内网，只需部署服务或发布通道具备受控访问能力。
- Figma 原生源文件通过约定的 Figma 文件归属、分享和 .fig 下载流程交付，业主仍无需访问 GitLab；.fig 副本可在内部仓库归档。

只有计划让外包设计师或外部开发人员直接参与仓库工作时，才另行评估外部账号和受控仓库访问；这不是业主自助设计的前提。是否需要公司申请新的私有项目及部署资源属于内部管理事项，不等于需要一个公开仓库。

### AI 费用由业主承担

**推荐默认模式：业主预充值额度，平台统一调用经批准的 AI 网关，按实际调用扣费。** 这样业主不需要自行申请模型账号，适合自助设计。平台在调用上游前预留本次任务的费用上限，任务完成后按实际用量结算并退回差额；余额不足不提交请求。公司账务上仍可能先向上游结算，再从业主预充值余额抵扣，需核对网关合同是否允许对业主提供此类服务，并明确费率、税费及发票流程。

**备选模式：业主自带 AI API Key。** 若供应商允许业主独立开通、模型可用且支持按账户直接计费，平台在服务端安全保存各业主密钥，调用时只使用当前业主的 Key；上游费用由业主直接向供应商支付。该模式能让费用直接归属业主，但增加密钥配置和排障负担，且现有公司网关不能假定支持业主自带 Key。可先作为高级选项，不作为首次使用门槛。

| 项目 | 必须实现的行为 |
| --- | --- |
| 计费主体 | 每次生成关联业主、项目、操作人、模型、任务及请求快照；不同业主不能共用无归属的付费任务 |
| 计费展示 | 上传、选集成库现成素材、页面本地拼接、调整颜色与字号不触发 AI 扣费；只有明确点击 AI 生图/重做时计费；提交前显示模型、预计调用次数、单价和本次预留上限 |
| 批量生成 | 展示素材清单和每项预计费用；业主可先生成样板，再按需生成剩余项；免费复用既有合规素材 |
| 账本 | 充值、预留、实际扣费、释放差额、异常调整均写入不可直接改余额的流水；提供业主可查看的项目用量明细 |
| 对账 | 记录上游请求 ID、模型、费率版本、上游实际计费或可核验调用结果；本平台账单与上游账单定期核对，处理重复响应及重试 |
| 失败与重试 | 任务失败时按上游实际是否收费结算；结果不确定时先标为待核对，避免直接重试造成重复付费；重复点击用幂等键阻止重复提交 |
| 额度控制 | 按业主设置余额和预算上限；限制单次批量规模、并发、每日额度，费用预留采用原子操作，避免并发透支 |
| 密钥安全 | 公司或业主密钥只留服务端，存入密钥管理服务或加密存储；不写入浏览器、项目 JSON、GitLab 仓库和交付包；提供轮换、停用与审计 |
| 定价变更 | 费率随模型/质量/分辨率变化时版本化，已提交任务沿用提交时的费率快照；充值币种、汇率、退款与发票规则在上线前确定 |

技术流程：业主选择素材槽位和生成参数 → 平台给出费用估算 → 业主确认提交 → 服务端原子预留额度并创建归属清晰的任务 → 服务器调用 AI → 保存结果与上游凭据 → 按结果结算并将候选素材放入该业主项目。只有“采用素材”才进入正式页面；单项重新生成是一笔新的付费任务，必须再次显示费用。

现有本地工具的单个公司网关密钥与全局任务锁，只适合作为能力验证。上线前必须改为按业主隔离的身份、队列、账本和密钥管理，不可直接把当前本地服务对外开放。

建议先用真实但受控的小额任务验证：网关是否提供可对账的任务/费用数据，是否允许对业主提供服务，任务失败是否收费，以及本平台能否在重复提交、重启和上游超时后正确结算。在这些信息确认前，不承诺精确按实际成本扣费；可暂用已公布的按次定价和预留上限，但必须明确价格与退款规则。

## 图标 @2x 输出（用户补充）

| 图标类别 | 规范逻辑尺寸 / Figma 展示尺寸 | @2x PNG 实际像素 |
| --- | --- | --- |
| 底部导航图标 | 70×70 | 140×140 |
| 中部导航图标 | 80×70 | 160×140 |
| 游戏类型图标 | 100×76 | 200×152 |

脚本流程：从矢量或足够清晰的高分辨率原图制作 → 按目标比例裁切或留边 → 输出精确 @2x PNG → 检查像素和透明通道 → 生成对应原尺寸的 Figma 图层并填入该图片。建议文件名包含 @2x，清单记录 logicalWidth、logicalHeight、pixelWidth、pixelHeight、scale=2。

Figma 图层分别保持 70×70、80×70、100×76，不按图片的原始像素创建两倍大小，也不把整页画布放大。750×1334 画布保持原定义。导出整页 PNG 时可提供 1x/2x 选项：1x 页面是 750×1334，2x 页面是 1500×2668；这与独立图标 @2x 是不同操作。

AI 图标先从较大原图处理到 @2x，使用高质量重采样并检查细节、透明边缘和整组视觉占比。对已经模糊的小图，单纯放大到 @2x 不会恢复细节，需要高分辨率源图、重绘或矢量资源。

SVG 保留真实路径时不需要 @2x，按规范逻辑宽高和 viewBox 导出；Figma 中可保留原生矢量和 Key 绑定。若 SVG 嵌入的是位图，则仍需检查所嵌图片分辨率，不能视为真实矢量。

验收：独立 PNG 实际像素符合 @2x；Figma 图层符合原规范；.fig 重开后图片显示、透明边缘与尺寸正确。默认/选中及其他图标状态采用一致倍率、对齐和视觉占比。后续工程接入需使用逻辑尺寸显示，避免把 @2x 当成两倍大的组件。

## 中部导航与底部导航的配置模式（用户补充）

创建或编辑导航组件时，业主分别选择一种模式；中部导航与底部导航可以采用不同模式。模式影响必须提供的图标清单与交付检查，不改变其逻辑尺寸和 @2x 输出规则。

| 模式 | 中部导航必交 | 底部导航必交 | 彩色 icon |
| --- | --- | --- | --- |
| 可后台配置 | 该版式后台可配置入口清单中的**全部 icon** | 该版式后台可配置入口清单中的**全部 icon** | 可选择性提供，不作为必交项 |
| 不可后台配置/固定入口 | 消息-已读、消息-未读、通知、公告；其他入口自行选配 | 首页、我的；其他入口自行选配 | 可选择性提供，不作为必交项 |

“全部 icon”以该项目所选产品版式及后台配置能力对应的正式入口清单为准，不能仅以当前预览页恰好显示的几个入口为准。业主选择“可后台配置”时，平台先展示该完整清单并逐一检查。后台可配置入口范围尚需与真实后台能力核对，不能凭设计说明中的可选图标推断所有入口均可配置。

固定入口模式下，选配其他入口后，该入口加入本项目的设计与交付清单；未选配的不计为缺失。中部导航的“消息-已读”和“消息-未读”是两张独立必交图标，通知与公告也各一张。底部导航首页、我的分别必交。

检查器同时按“配置模式、入口、状态、彩色变体、尺寸倍率、文件格式”记录每个图标。普通必交 icon 缺失阻止完成交付；彩色 icon 缺失只显示未提供，不阻止交付。彩色变体不得替代普通必交 icon；已读与未读也不能共用同一个文件冒充两种状态。

切换配置模式时，先显示必交清单的变化与已有素材的复用情况；已设计的图标保留在项目素材中，不自动删除。交付 manifest 记录模式、完整入口清单、必交/选配状态以及各图标 1x 逻辑尺寸和 @2x 实际像素，供后台接入核对。

## 图标设计款式与配套提示词（用户补充）

图标 AI 生成入口提供若干由内部维护的设计款式供业主参考，每款配套参考图与提示词。具体款式数量和正式示例以内部提供的内容为准，不在方案阶段虚构已完成素材。

款式记录包括：款式名称、真实参考图、适用图标类别、提示词模板、支持的单色/彩色表现、推荐描边与立体程度、构图与留白要求，以及款式版本。单色/彩色是视觉变体，不改变导航配置模式的必交清单；彩色图标仍为可选。

操作流程：选择底部导航/中部导航/游戏类型图标 → 选择参考款式 → 选择入口与必要状态 → 系统带入配套提示词、项目主题、对应 Key 及规范尺寸 → 业主可补充图标含义或设计要求 → 查看费用并提交生成 → 检查 @2x 像素、透明边缘和视觉占比 → 采用候选并回填页面。

提示词采用“款式公共要求 + 图标语义 + 状态要求 + 项目配色 + 输出约束”组成。入口语义与状态必须分别填写，例如消息已读/未读，不能仅替换文件名。项目配色解析自当前 Key 映射，模型接收的是本次已解析颜色与参考图；模型不直接持有平台变量绑定。

业主可以查看并编辑允许修改的设计描述；规范宽高、@2x 倍率和最终像素检查由系统管理，不能因修改提示词绕过。适用类别以款式登记为准，避免把不适合小图标的细节丰富款式强行套到导航中。

整组图标共用同一款式和已采用的样板参考。先生成并确认一个样板，再生成剩余必交与已选配入口；批量前显示实际调用数量和费用。模型生成只作为候选，一致性、清晰度和状态辨识度需要检查。AI PNG 仍为位图；需要真正可编辑的 SVG 图标时，选用真实矢量款式/素材或另外验证矢量生成流程，不能将 PNG 改后缀交付。

参考款式浏览、提示词套用与编辑不扣 AI 费用；提交 AI 生成或重做才计费。项目保存款式版本、提示词快照、生成参数和素材采用记录，便于单项重做及整组恢复。

## 关键提示词的效果预览（用户补充）

关键视觉词以带文字的效果标签呈现，例如玻璃质感、磨砂、金属、立体、发光、描边。具体词库与示例图由内部维护；不为每个普通语义词强制增加效果图。

- 桌面鼠标悬停或键盘聚焦标签时显示效果预览浮层，包含词名、对应参考图和一句效果说明。预览不自动选中该词，点击标签才添加/取消。
- 手机点击预览入口打开详情，提供明确的“采用该效果”操作；关闭预览不修改提示词。悬停不能成为唯一访问方式。
- 同类互斥效果提供单选规则；可叠加效果允许组合，并提示不适合小尺寸图标或可能冲突的组合。
- 参考图优先使用同一图标主体、相同背景和视角，让业主容易比较玻璃、磨砂、金属等效果。浮层图足够清晰，可打开大图，并可查看原尺寸图标表现，避免只看放大细节。
- 预览使用预先制作并缓存的真实示例素材，不在悬停时实时调用 AI、不收费。标明“效果参考”，不暗示多个词组合后必然得到该结果；实际项目效果通过付费候选生成确认。
- 每个标签保存稳定词条 ID、中文名称、生成描述、预览素材、适用范围、兼容/互斥规则和版本；提示词拼接使用生成描述，不把帮助说明混入请求。
- 浮层需支持鼠标移入查看、键盘关闭、屏幕边界避让和短延迟，避免快速扫过标签时闪烁；参考图片按需加载并预留尺寸。

验收：悬停与键盘聚焦均能预览，预览不触发选词或 AI 请求；点击采用后完整提示词正确更新；手机能查看并采用；原尺寸预览与 @2x 展示正确；示例缺失时明确提示，不显示虚构效果。

## 提示词库改为定制设计用途（用户补充；仅方案）

用户要求提示词库针对版式风格，以及侧边栏、中部导航、底部导航的图标风格和质感。当前行业导向词库的筛选及分类不继续作为该入口的主体；本节只修订方案，不修改当前代码。

### 一级分类

| 分类 | 内容 | 应用对象 |
| --- | --- | --- |
| 版式风格 | 整体视觉方向、层次、留白、底板及装饰表现等风格描述，配页面参考图 | 当前项目/页面的风格参考；实际布局仍由选定模板与组件配置决定 |
| 侧边栏图标 | 图标风格、质感、描边、圆角、立体程度等视觉要求 | 侧边栏内部入口图标；顶部栏打开侧边栏的按钮仍单独登记 |
| 中部导航图标 | 适合中部导航的图标风格与质感，配真实参考 | 中部导航入口及消息已读/未读、通知、公告等状态图标 |
| 底部导航图标 | 适合底部导航的图标风格与质感，配真实参考 | 底部导航入口及选中/未选中等状态图标 |

导航图标分类下以“风格”“质感”作为主要选词组，其他细节按需展开。可使用扁平、线性、立体，以及玻璃、磨砂、金属等直观名称作为候选分类示例；正式可用词条、款式及预览图由内部整理后登记，不能虚构已存在素材。

### 业主操作

业主先选用途，再看款式与效果，点击采用即可更新当前设计要求；无需理解九类旧提示词结构。提供清晰的已选标签与移除操作，并保留一句自然语言的补充要求。

关键风格/质感词悬停或键盘聚焦展示参考效果，手机可点击查看并采用。预览使用预制素材，不实时调用 AI，不收费。整套款式可携带一组相容词；互斥项单选，可叠加项允许组合，不适合小尺寸图标的效果标明适用限制。

### 与项目及生成的绑定

选词要应用到明确对象：当前页面风格、当前图标或当前一组图标。页面风格采用前预览影响范围，不自动替换已确认版式；修改一张图标也不能自动覆盖整组。

词条只表达视觉要求。生成时系统另行补齐图标含义、所属入口、状态、规范尺寸、@2x 规则、项目配色 Key 的解析值及已采用样板参考。中部与底部导航的必交清单仍由配置模式决定，不由词条选择决定。

不同用途可以复用同一基础风格词，但分别登记适用范围和预览，避免只改分类名仍使用原来的行业词。侧边栏图标不得自动套用中部或底部图标的尺寸；其规格由对应组件规范确定。游戏类型图标仍保留已确定的设计能力，可复用适用款式，但本次不擅自增设第五个一级分类。

选择和编辑提示词不生成文件、不扣费；点击 AI 生成才展示费用并提交。生成结果默认是候选素材，采用后进入页面；版式风格描述不等于自动生成完整可编辑 Figma 页面。

### 验收

提示词库一级分类与上述四类一致；词条及真实参考与用途匹配；关键效果能预览；采用与移除正确更新指定对象；尺寸、配色、必交状态及收费规则保持独立；旧词库原始资源可保留但不混入新的默认界面。

默认首页使用完整模板，业主可在允许范围内替换、排序、拼接、显示/隐藏模块。侧边栏、固定底部导航、页面内容区和弹窗/悬浮层使用各自的布局规则，不能将九个模块简单视为九张图片堆叠。必需功能、模块兼容性和可移除范围在模板登记时明确。

九个区域均提供各自的布局选择，不仅依赖整页模板；区域布局缩略图与当前页面即时预览结合，具体参考及迁移规则见「区域独立布局选择」。

Figma 源文件按九个模块组织清晰命名的 Frame/组件与内部图层，保留主题 Key、规范逻辑尺寸及 @2x 图片。独立素材按规范输出；模块截图按其页面展示尺寸输出；整页 PNG 按页面尺寸输出，导出界面区分这三类结果。

## 顶部栏：已登录与未登录状态（用户补充）

顶部栏采用同一组件的两个状态，业主在编辑器中切换“未登录 / 已登录”即可预览和编辑。

顶部栏逻辑高度限制为 **70–100px（含上下限）**。编辑器用有上下限的高度控件，不允许拖动或输入超出范围；Figma 图层使用相同逻辑高度。两种登录状态默认共享高度及背景，避免切换状态时页面跳动。宽度依当前页面和版式确定，不由高度规则推导。

LOGO 资源规范为：**宽度 330–600px（含上下限），高度固定 100px**。资源上传/采用时校验原始尺寸；不合规时提示调整并预览，不静默拉伸。LOGO 不属于三类导航图标的 @2x 规则，保留其单独资源规范。

LOGO 页面显示尺寸根据已确定的顶部栏高度等比缩放：以原图 100px 高度为基准，顶部栏高度为 H 时，基础缩放比例为 H/100；显示高度为 H，显示宽度为原始宽度×H/100。例如原图 600×100，顶部栏 70px 高时显示为 420×70；原图 330×100 则显示为 231×70。需要内边距或避免与其他入口重叠时，可在此比例内进一步等比缩小并居中，保留宽高比，不强制拉伸填满区域。

顶部栏高度变化只更新 LOGO 的页面摆放尺寸，不改写原始 LOGO 文件，也不触发 AI 生成。Figma 使用原始图片资源创建对应显示尺寸的图层，独立 LOGO 导出保持 330–600×100px 原始规范；页面/模块导出按实际显示尺寸渲染。必须验证 70px 与 100px 两种边界高度下，LOGO 和同栏图标、按钮或余额框不会相互遮挡。

背景提供“配色 / 图片”两种模式：

- 配色模式：背景填充绑定 **bs_topnav_bg**，业主选色或改变引用规则后更新该 Key；已锁定元素保持此绑定，不写成无关联的 HEX。
- 图片模式：允许上传、选择集成库素材或 AI 制作背景，显示实际顶部栏尺寸的预览并提供裁切/铺放处理；LOGO、图标、文字、按钮与余额框保持独立图层，不合进背景图。
- 图片下方保留绑定 bs_topnav_bg 的底色，用于透明区域、加载过程或图片缺失；切回配色模式时复用原 Key 配色，不丢失已设置颜色。透明区域可见底色，完全不透明图片则覆盖底色。
- 高度改变后，图片按当前显示区域重新预览，检查主体裁切、元素边距和文字可读性。变更仅需重新排版/裁切时不调用 AI、不扣费；主动重生成背景才显示费用并提交。

Figma 源文件保留 bs_topnav_bg 背景底色层/绑定及独立图片背景层，组件实际高度须在 70–100px 范围内。图片模式不能通过导出一张含所有内容的顶部栏图片代替可编辑源文件。

两种状态共享 LOGO、入口图标和基础外观，状态专属元素单独编辑；共用素材修改后同步到两个状态。余额框保留独立可编辑的金额文字层，以短金额、长金额及不同货币显示测试布局，不能将金额固定烘焙在图片里。字体、图标、框体与按钮配色按用户色值规范绑定，具体 Key 由对应版式的元素语义登记确定。

Figma 源文件采用明确命名的两种组件变体或状态 Frame，保留全部状态内部图层和 Key 绑定。导出 PNG/SVG 支持选择状态或导出两种状态，文件名与 manifest 标明已登录/未登录。顶部栏状态切换需与首页整体状态保持一致，避免未登录首页显示余额框。

验收：高度上下限 70/100px 可用，超限不可保存；两种状态内容完整，登录/注册按钮与余额框正确切换；配色模式实际绑定 bs_topnav_bg，图片模式预览、裁切和底色正确；共享素材一致；不同文案、语言及金额长度不会挤压 LOGO 或入口；Figma 源文件能修改状态专属元素并保留共用关系。

## 首页 Banner 与轮播指示器（用户补充）

Banner 默认尺寸选择提供三项，首页采用相同规格目录：**01 大 Banner 1080×490px、02 通用 Banner 1020×300px、03 小 Banner 386×244px**。资源必须符合所选实际像素，在首页对应版式区域等比显示；同一轮播组统一规格，避免切换时高度跳动。小 Banner 的摆放区域及排列按版式定义，不能因加入规格就默认拉伸铺满整页宽度。

Banner 样式预览来源固定为用户指定的 [皮肤组件库 / Banner多样式 / 1594:6679](https://www.figma.com/design/10vz65hunghJhuMqeuHyUw/?node-id=1594-6679)。已只读核对该节点为「02 ◆ 组件」页的组件集，包含 APP/H5/PC 的大、通用、中、轮播及小 Banner 展示变体。平台按当前端展示适用的真实参考缩略图，预览获取和素材缓存待实现阶段完成，不把本次只读登记描述为已接入。

该组件集中的页面展示尺寸与后台上传资源规格不同，例如 H5 大 Banner 展示为 750×340、通用 Banner 展示为 710×210；这类尺寸不是新的上传规格。中 Banner、轮播 Banner 是该库中的展示样式名称，不自动新增到用户确定的三项资源尺寸目录。每个样式需要在模板整理时登记其资源规格、内部素材区域、显示尺寸与铺放方式；若参考容器与资源比例不同，明确裁切/留边并让业主预览，不静默拉伸。首页 Banner 的正式独立素材仍按 1080×490、1020×300 或 386×244px 输出。

### 业主选择流程

1. 点击页面中的区域，或从首页九模块清单选择。
2. 打开「换布局」，看到少量精选缩略图、简单名称及当前已采用标记，可展开查看更多。
3. 点选候选后在自己的页面中预览，带入自己的配色、文字与素材；不只展示静态参考截图。
4. 预览需要补齐的内容和布局变化，点击「采用布局」后保存；关闭预览不改变当前设计，支持撤销。

布局选择、预览和复用现有素材不调用 AI、不扣费。需要新增或重做素材时单独列出项目和费用，由业主明确提交。

### 布局切换的保留与约束

- 保留项目 11 个基础色及完整 68-Key 规则，组件按语义重新解析颜色；参考副本里的配色不能覆盖业主主题或已锁定绑定。
- 按入口 ID、状态和素材槽位语义迁移已采用内容，不按图层名称相似或当前颜色相同猜测映射。
- 保留已登录/未登录、选中/未选中、消息已读/未读等状态；新布局缺少必要状态时不能作为合格选项。
- 顶部栏仍限制 70–100px，LOGO 仍保持资源规范与等比展示；导航图标和卡片仍执行原规范及倍率。布局参考不能绕过尺寸限制。
- 中部/底部导航的后台配置模式是独立设置，不因换外观就改变。无法迁移的入口或素材先标明，由业主补齐；旧设计保存在上一版，不自动删除。
- 布局适用端、等级、区域、内部间距、固定/流式方式及所需功能由管理员登记；界面只显示当前项目适用选项。布局切换后检查页面溢出、固定层遮挡和长文案。
